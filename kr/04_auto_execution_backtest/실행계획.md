# 레이어 4 — 자동 실행과 검증 (5~6장) 실행 계획

## 지금까지 확정된 것
- 실전 자동매매(실계좌 주문)까지는 아직 안 감 → **모의투자 + 백테스팅까지만** 진행
- 손절/익절 기준 → 백테스팅 결과 보고 나중에 확정
- 매매 스타일(모멘텀/회귀/돌파) → 아직 미확정

## 추가로 결정해야 할 것들

### 1. 백테스팅은 증권사 API 없이도 시작 가능
백테스팅 자체는 과거 시세 데이터만 있으면 되고, 굳이 키움/한투 API를 먼저 연결할 필요는 없다.
데이터 소스 후보: Yahoo Finance(무료, 한국 종목도 `005930.KS` 형식으로 조회 가능), 네이버 금융, 한국투자증권(KIS) Open API의 과거시세 조회.
→ **바로 시작 가능**: 3가지 매매 스타일(모멘텀/회귀/돌파)을 삼성전자 등 대상 종목에 대해 과거 1~3년 데이터로 각각 백테스트하고 성과(승률, 손익비, MDD)를 비교해서 스타일을 정하는 방식을 제안.

### 2. 모의투자 API 선택 — 기술적 제약 확인 필요
책은 "키움증권 OpenAPI"를 예로 들지만, 실제로 키움 **OpenAPI+(구버전)**는 Windows 32비트 + ActiveX 기반이라 이 클라우드(Linux) 환경이나 일반 서버에서는 실행이 안 된다. 대안은 두 가지:
- **한국투자증권(KIS) Developers API**: 순수 REST/WebSocket 기반이라 OS 상관없이 클라우드에서 바로 연동 가능, 모의투자 계좌도 지원. (추천)
- 키움도 최근 REST 기반 오픈API를 일부 제공하기 시작했다면 그걸 쓰는 방법도 있음 — 확인 필요
→ 클라우드 환경에서 지속적으로 자동화하려면 **KIS Developers API 모의투자**로 가는 걸 추천. 신준님 명의로 증권사 계좌 + API 신청이 필요해서, 이 부분만 신준님이 직접 가입/키 발급을 진행해주셔야 함.

### 3. 백테스팅 대상 종목 / 기간
- 삼성전자만? 아니면 앞서 섹터 로직에서 나온 SK하이닉스, LG에너지솔루션 등도 포함?
- 기간: 최근 1년 / 3년 / 5년 등

### 4. 리스크 관리 파라미터화
- 손절/익절 %(고정) vs 트레일링 스탑 vs ATR 기반 — 여러 버전을 백테스트에서 같이 비교해보고 뭐가 잘 맞는지 데이터로 정하는 방식 제안

### 5. 업그레이드 루틴 (책이 강조한 3단계) — 자동화 예정
- **주간 리뷰**: 매주 한 번 그 주의 매매전략/매매일지를 되돌아보고 문제 없는지 점검
- **월간 백테스팅 업데이트**: 매달 최신 데이터를 반영해 전략 성과 재검증
- **지속 학습**: 새로운 패턴/이슈 발견 시 판단로직.md, 점수제_판단로직.md 등에 계속 반영
→ 실제 백테스트 엔진과 매매전략 시스템이 어느 정도 자리 잡으면, 이 3개를 각각 스케줄 작업(주간/월간)으로 등록할 계획

## 책이 "방향"만 알려주고 넘어간 디테일 — 우리가 직접 정해야 하는 것들 (백테스트 설계용)

책은 "모멘텀/회귀/돌파 중 성향에 맞게 고르고, 손익절 정하고, 백테스트해봐라"까지만 말하고 구체적 파라미터는 안 알려준다. 실제로 백테스트를 돌리려면 아래를 정해야 값이 나온다. 각 항목에 기본값(추천)을 제안하니, 그대로 가도 되고 바꿔도 된다.

| 항목 | 왜 필요한가 | 기본값 제안 |
|---|---|---|
| 대상 종목/유니버스 | 단일 종목만? 여러 종목 포트폴리오? | 삼성전자 단일 종목으로 먼저 (이후 SK하이닉스 등 확장) |
| 백테스트 기간 | 상승장/하락장 다 포함해야 신뢰도 있음 | 최근 3년 (여러 국면 포함) |
| In-sample/Out-of-sample 분리 | 과거 데이터에 과최적화(과적합)되는 것 방지 | 앞 2년 파라미터 튜닝용, 최근 1년은 검증용으로 딱 1번만 확인 |
| 데이터 주기 | 일봉 vs 분봉 — 우리 RSI/MACD 로직은 일봉 기준으로 설계됨 | 일봉 |
| 초기자본금 / 포지션 사이징 | 수익률(%) 계산 기준 | 초기자본 1,000만원 가정, 매매당 비중 고정(예: 20%) |
| 모멘텀 전략 구체 조건 | "모멘텀"이라는 말만으론 코드가 안 나옴 | 20일 이동평균 상향 돌파 + 우리 점수제(거시+RSI/MACD) 3점 이상일 때 진입 |
| 회귀(평균회귀) 전략 구체 조건 | 동일 | RSI(14) 30 이하 진입, 50~60 도달 시 청산 |
| 돌파매매 전략 구체 조건 | 동일 | 20일 신고가 돌파 + 거래량 평소 대비 150% 이상일 때 진입 |
| 손절/익절 후보 | 비교 대상이 있어야 "데이터로 결정" 가능 | 3가지 버전 동시 비교: ①고정 -3%/+6% ②트레일링 5% ③ATR×2 변동성 연동 |
| 수수료/세금 가정 | 반영 안 하면 실제보다 성과가 부풀려짐 | 매매 수수료 0.015% + 매도 시 거래세 0.15% 가정 |
| 동시 보유/거래 빈도 제한 | 무제한이면 비현실적 | 동시 보유 1종목(삼성전자 단일이라 자동 해당), 하루 최대 1회 진입 |
| 성과 비교 기준 | 승률만 볼지, 손익비/MDD도 볼지 | 총수익률 + 승률 + 손익비 + MDD(최대낙폭) + 코스피 지수 대비 초과수익 |

이 표대로 진행해도 되고, 표의 어떤 항목이든 바꾸고 싶으면 그 부분만 짚어서 말씀해주시면 반영해서 백테스트 돌릴게요.

## 제안하는 다음 순서
1. (지금 바로 가능) 모멘텀/회귀/돌파 3개 전략을 삼성전자 과거 데이터로 백테스트하는 스크립트 작성 + 실행 → 성과 비교
2. 비교 결과 보고 매매 스타일 + 손절/익절 기준 결정
3. KIS 모의투자 API 신청 (신준님 진행) → 연동
4. 주간 리뷰 / 월간 백테스팅 업데이트 스케줄 작업 등록
